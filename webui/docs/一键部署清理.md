# DMR_WebUI 一键部署与清理

## 推荐结构：一个入口、两套引擎

新增文件全部放在 WebUI 子仓库的 `webui/deploy/`：

| 文件 | 责任 |
| --- | --- |
| `deploy_webui.sh` | WebUI 环境、哈希锁、禁网测试、纯净快照、可选回环启动 |
| `cleanup_webui.sh` | WebUI 运行期清理、账本备份 retention、保护校验、可恢复隔离 |
| `deploy_all.sh` | 薄编排：DMR 根部署 → WebUI 部署 |
| `cleanup_all.sh` | 薄编排：停止 WebUI → WebUI 清理 → DMR 根清理 |

内部逻辑不合并。DMR 仍由根目录现有 `deploy_and_run.sh` 和
`cleanup_deployment_files.sh` 管理；WebUI 仍由自己的引擎管理。

## 入口参数与顺序

四个脚本都使用 `--preview`、`--execute --yes/--confirm` 的确认契约；聚合入口
还支持 `--scope all|dmr|webui`（以及 `--dmr-only`、`--webui-only`）。

```bash
# 正式操作前只生成计划与证据
webui/deploy/deploy_all.sh --preview --scope all --tests none
webui/deploy/cleanup_all.sh --preview --scope all

# 只部署 WebUI；不调用 DMR 根脚本
webui/deploy/deploy_all.sh --execute --yes --scope webui --tests both

# 只清理 DMR；不停止 WebUI
webui/deploy/cleanup_all.sh --execute --yes --scope dmr

# 全部执行（顺序固定，任一步失败短路）
webui/deploy/deploy_all.sh --execute --yes --scope all --start
webui/deploy/cleanup_all.sh --execute --yes --scope all
```

部署聚合的 preview 不调用 DMR 根脚本，因为根脚本没有 preview 参数；preview 只
调用 WebUI 引擎的只读计划并打印将执行的根命令。清理聚合的 preview 调用根脚本
的 `check`，不停止服务、不移动文件。清理 execute 先调用已有 `dev_stop.sh`，
若停止失败则不进入任何清理步骤；WebUI 清理失败则不调用 DMR 清理。

每次聚合运行创建项目外的 `run-*` 证据目录，顶层 `result.json` 汇总步骤状态，
各组件保留自己的日志/result。所有脚本将 `live_trading_enabled` 记录为 false；
`--start` 只启动替身环境，且最终必须确认已停止开仓。

## 与现有 DMR 文件的边界

- 当前 `cleanup_deployment_files.sh` 已将 `webui` 放入排除清单，故不重复修改。
- 当前根 `deploy_and_run.sh` 的纯净快照仍只排除自身 `venv/.git`。本次新增入口
  不擅自修改它；正式执行若需要把 `webui/` 加入排除，必须另行明确授权后再做
  单点修改和验收。
- 不安装、不启用 systemd 模板；使用既有 `dev_start.sh`、`dev_stop.sh`、
  `dev_status.sh` 作为当前运行边界。

## 依据与验证边界

本实现结合当前项目源码、测试入口和开发部署记录。内部 Claude 会话、计划报告、运行日志及验收
截图属于发布前审计资料，不随公开仓库分发；公开版本只保留可由源码复核的部署顺序、保护规则、
回环边界和证据格式。WebUI 的两套 Python 3.12 环境与 hash 锁见 `requirements/`，禁网测试入口
见 `run_tests.sh`，启停顺序、0600 凭据文件和备份演练见 `docs/运行手册.md`。

本轮只创建脚本和说明，并做 `bash -n`、帮助输出及预览验证；没有执行真实部署、
重建环境、停止服务或移动文件。正式 execute 前应先审阅 preview 的
`result.json`，确认当前进程状态和候选清单。
