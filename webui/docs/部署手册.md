# WebUI 部署引擎操作说明

对应程序：`webui/deploy/deploy_webui.sh`。它只管理 WebUI 的两个 Python 3.12
环境和 WebUI 运行期，不把 DMR 的安装逻辑复制进来。

## 安全边界

- 默认是预览模式，不创建虚拟环境、不安装依赖、不启动进程。
- 执行必须显式给 `--execute --yes`（或 `--execute --confirm`）；单独给确认参数
  或同时给 `--preview`/`--execute` 会拒绝。
- 执行会持有项目外的操作锁；已有部署/清理运行时拒绝并发。
- 只使用 `requirements/kernel-dev.lock` 和 `requirements/console-dev.lock` 安装；
  同时校验四个带 `sha256` 的 lock 文件，安装顺序是 `pip --dry-run`、实际
  `--require-hashes --no-deps`、`pip check`。
- 使用系统 Python 3.12 建立 `.venv-kernel`、`.venv-console`；已有不健康环境
  默认拒绝，`--rebuild` 会先把旧环境 rename 到外部证据目录，绝不直接删除。
- 执行前后做纯净快照。`.git`、两个虚拟环境、`var/`、`backup/` 和缓存目录
  属于运行期排除项；源码、文档和 lock 文件变化会使部署失败。`.env`、token、
  password、secret 等敏感文件只记录权限/大小/时间元数据，不读取或写入摘要。
- 测试只通过项目自己的 `run_tests.sh kernel|console` 运行，使用禁网包装，
  不在项目根目录运行裸 `pytest` 或裸解释器。
- `--start` 才会调用既有 `dev_start.sh`（替身环境、仅回环）；启动后用本机
  控制接口确认 `开仓闸：已停止开仓`。默认不开启进程，也不安装 systemd。
- `--operator NAME` 只能和 `--start` 一起使用。已有 `0600` 口令文件不覆盖；
  新口令由内核 CLI 生成并只写入 `var/operators/NAME.password`，脚本不会读取或
  回显口令。

## 常用命令

```bash
# 只看计划（推荐先运行）
webui/deploy/deploy_webui.sh --preview --tests none

# 建环境、严格安装、禁网空测，不启动服务
webui/deploy/deploy_webui.sh --execute --yes --tests both

# 在确认环境后启动替身回环栈并确认停止开仓
webui/deploy/deploy_webui.sh --execute --yes --start --tests both

# 首次创建操作员（口令只落 0600 文件）
webui/deploy/deploy_webui.sh --execute --yes --start --operator admin
```

`--evidence-dir DIR` 可将证据写到指定的项目外目录。每次执行会留下
`result.json`、`purity-before.json`、`purity-after.json`；证据目录建议权限为
`0700`。部署门禁同时检查 pid 文件和 `/proc` 中的 WebUI 进程；当前已有进程时，
部署/重建会拒绝执行，请先用 `dev_stop.sh` 停止。

## 失败处理

脚本遇到锁校验、环境健康、测试、快照或闸门检查失败会立即停止；不会继续启动
或执行其他组件。外部证据目录和旧环境备份保留，依据 `result.json` 的
`last_step` 定位原因；若本次 `--start` 后续校验失败，脚本会尝试停止本次启动的
WebUI 栈。部署器不修改 DMR 根目录的 `deploy_and_run.sh`，也不声称已部署 systemd。
