# WebUI 清理引擎操作说明

对应程序：`webui/deploy/cleanup_webui.sh`。清理是可恢复隔离，不是删除；目标
文件被同文件系统 `rename` 到项目外的 quarantine 目录，并记录 `journal.jsonl`。

## 默认与保护

- 默认只预览；执行必须 `--execute --yes`（或 `--execute --confirm`）；单独给确认参数
  或同时给 `--preview`/`--execute` 会拒绝。
- 清理会持有与部署共用的项目外操作锁；已有部署/清理运行时拒绝并发。
- 运行中的 standin、kernel、supervise、console，或 `/proc` 扫描发现仍占用
  WebUI 路径时，执行一律拒绝，不移动任何文件；`/proc` 相关权限/读取错误也会
  作为 `scan_errors` 阻断执行。
- 候选仅包括 Python/NiceGUI/pytest 缓存、`var/log/` 日志、失效 `var/run/*.pid`
  和过期的 `backup/ledger-*.sqlite`。
- 永久保护：`.venv-kernel`、`.venv-console`、四套 lock/in 文件、
  `var/kernel/ledger.sqlite` 及 WAL/SHM、kernel/standin token、
  `var/operators/*.password`、`var/console/session.secret`、kernel lock、
  停用标记和运行锁。保护对象执行前后做元数据/哈希比对；账本、token、口令、
  session secret 等敏感对象只记录元数据，不计算内容摘要。
- 备份默认保留最近 30 天，并且永远保留最新 2 份及名称含 `pre-upgrade` 的备份。
  `--retention-days N`、`--keep-backups N` 可调整；旧备份只进隔离目录，不释放
文件系统块。保留期限有可审计的 cutoff/kept 列表。

清理器会检查 pid 文件和 `/proc` 的 cwd/exe/fd/maps；任何扫描权限错误或不可读
状态都会作为 `scan_errors` 写入结果并阻断执行，不会把完整命令行写入证据。
因此正式 execute 需要执行账户能够读取相关 `/proc`；预览仍可生成计划，但权限
不足时会保持 fail-closed，不会移动文件。

## 常用命令

```bash
# 预览，不停止服务、不移动文件
webui/deploy/cleanup_webui.sh --preview

# 预览并指定备份保留策略
webui/deploy/cleanup_webui.sh --preview --retention-days 30 --keep-backups 2

# 先确认已停止 WebUI，再执行可恢复隔离
webui/deploy/cleanup_webui.sh --execute --yes --retention-days 30 --keep-backups 2
```

证据目录默认为项目外的 `.dmr-webui-cleanup`，也可用 `--evidence-dir` 指定同一
文件系统上的外部目录。`result.json` 至少记录 `status`、候选/移动/剩余列表、
进程检查、保护前后是否一致、quarantine 路径和 `filesystem_blocks_freed=false`。

## 恢复

不要手工删除 quarantine。按 `journal.jsonl` 的 `source`/`destination` 对照，
在确认项目没有并发写入后逐项反向 `mv`；恢复动作应另行留证。清理器本身不自动
回滚部分成功的隔离，以保留明确的恢复边界。
